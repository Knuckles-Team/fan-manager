# CONN-FAN-MANAGER — Requirements

Governing spec: [spec.md](spec.md).

Each row is one requirement. A row names the file it touches and the test that proves it.

| ID | Requirement | Acceptance |
|---|---|---|
| `CONN-FAN-MANAGER-R001` | **Ingest tools stay served.** The server must serve the telemetry ingest operations as the typed tools `fan_ingest_telemetry_temperature` and `fan_ingest_telemetry_sensors`. | `tests/test_served_surface_keeps_ingest.py` rows R001.1 to R001.5 pass. |
| `CONN-FAN-MANAGER-R001.1` | **Ingest actions served.** The served set must contain `fan_ingest_telemetry_temperature` and `fan_ingest_telemetry_sensors`. Caller chain: the fan-manager-mcp console script (scion_sdk.cli:serve) loads fan_manager:connector (fan_manager/__init__.py:90), whose tool_registry TOOL_REGISTRY (fan_manager/mcp_server.py) registers register_kg_tools (fan_manager/mcp/mcp_kg.py:26), defining fan_ingest_telemetry_temperature and fan_ingest_telemetry_sensors in mcp_kg.py. Shape: two typed tools registered through Connector(tool_registry=...); the test lists names with scion_sdk.mcp.tool_surface.registered_tools. | `tests/test_served_surface_keeps_ingest.py::test_ingest_telemetry_actions_are_served_as_tools` must pass. |
| `CONN-FAN-MANAGER-R001.2` | **Daemon loop is not a tool.** The served set must not contain a tool for `run_service`, because the daemon loop runs as the CLI service. Caller chain: fan_manager:connector (fan_manager/__init__.py:90) passes api=_OperationApi (fan_manager/mcp_server.py:33) to Connector, so the SDK surface built for the fan-manager-mcp console script has no run_service method; the CLI fan-manager entry point fan_manager.fan_manager:fan_manager (fan_manager/fan_manager.py:501) runs the loop. Shape: _OperationApi subclasses Api and sets run_service = None so the SDK skips it when registering tools; the daemon loop stays the run_service function called by fan_manager(). | `tests/test_served_surface_keeps_ingest.py::test_run_service_is_not_a_tool` must pass. |
| `CONN-FAN-MANAGER-R001.3` | **Shared SDK floor.** The package must require `scion-sdk[mcp]>=0.9.0,<0.10.0` in `pyproject.toml`, because older releases lack the typed surface contracts the connector declares. Caller chain: the dependency pin in pyproject.toml (dependencies list) is resolved at install time, and scion_sdk.cli:serve behind the fan-manager-mcp console script relies on the SDK split surface it provides. Shape: one dependency string scion-sdk[mcp] with a floor and an upper bound in pyproject.toml; the test parses pyproject.toml and checks the floor. | `tests/test_served_surface_keeps_ingest.py::test_sdk_floor_is_declared_for_the_split_surface` must pass. |
| `CONN-FAN-MANAGER-R001.4` | **Wiring.** `fan_manager/mcp_server.py:69` must call `register_tool_surface` with the temperature, fan-control, and knowledge-graph tool registries. Caller chain: the fan-manager-mcp console script (scion_sdk.cli:serve) loads fan_manager:connector (fan_manager/__init__.py:90), whose tool_registry=tuple(TOOL_REGISTRY) from fan_manager/mcp_server.py names register_temperature_tools, register_fan_control_tools and register_kg_tools; the SDK registers them through register_tool_surface. Shape: TOOL_REGISTRY is a list of (tag, env-toggle, registrar) tuples in fan_manager/mcp_server.py; the registrars live in fan_manager/mcp/mcp_temperature.py, mcp_fan_control.py and mcp_kg.py, and the SDK Connector does the register_tool_surface call (the row line number 69 is stale since mcp_server.py has no such call). | `tests/test_served_surface_keeps_ingest.py::test_client_lists_ingest_tools_through_the_real_server` must reach that call. |
| `CONN-FAN-MANAGER-R001.5` | **Hot-path proof.** An MCP client connected to the production server object must list 39 tools, including both ingest tools. Caller chain: the fan-manager-mcp console script (scion_sdk.cli:serve) builds the server from fan_manager:connector (fan_manager/__init__.py:90); an MCP client lists tools over that server, as the test does through scion_sdk.connector.build_server("fan_manager"). Shape: the test builds the production server with build_server and counts tools with registered_tools plus an in-process fastmcp Client; no fan_manager code counts tools. | `tests/test_served_surface_keeps_ingest.py::test_client_lists_ingest_tools_through_the_real_server` must pass. |
| `CONN-FAN-MANAGER-R002` | **Per-node read endpoint.** When `FAN_MANAGER_NODE_API_PORT` is set, each fan-manager daemon must serve a read-only HTTP endpoint for its own server's BMC, from `fan_manager/node_api.py`. | `tests/test_fleet_endpoints.py` rows R002.1 to R002.3 pass. |
| `CONN-FAN-MANAGER-R002.1` | **Reads served, writes refused.** The node endpoint must answer `GET /health` and `GET /v1/<operation>`, and must answer 405 to every other method. Method filtering precedes authentication, so unsupported methods remain 405 without a token. Caller chain: the fan-manager console script (fan_manager.fan_manager:fan_manager, fan_manager/fan_manager.py:501) calls start_from_env (fan_manager/node_api.py:138) at fan_manager.py:584, which starts make_server (node_api.py:123) with _Handler.do_GET (node_api.py:98) and _refuse (node_api.py:117) for other methods. Shape: stdlib ThreadingHTTPServer with _Handler in fan_manager/node_api.py; do_POST, do_PUT, do_PATCH, do_DELETE, do_HEAD and do_OPTIONS all alias _refuse, which sends 405 before _authorized is consulted. | `tests/test_fleet_endpoints.py::test_node_endpoint_serves_reads_and_refuses_writes` must pass. |
| `CONN-FAN-MANAGER-R002.2` | **Read operations only.** The node operation set `READ_OPERATIONS` must name only BMC reads. It must not name a fan-level, power, boot, BMC user, LAN set, event-log clear, controller reset, or raw command. Caller chain: the fan-manager console script (fan_manager/fan_manager.py:501) starts the node endpoint through start_from_env (fan_manager/node_api.py:138); _Handler.do_GET (node_api.py:98) dispatches only names found in READ_OPERATIONS (node_api.py:42). Shape: READ_OPERATIONS is a dict of name to zero-argument callable over fan_manager.ipmi read verbs and get_temp; the test asserts its keys against a denylist of write verbs. | `tests/test_fleet_endpoints.py::test_node_read_operations_are_reads_only` must pass. |
| `CONN-FAN-MANAGER-R002.3` | **Bearer token.** When `FAN_MANAGER_NODE_API_TOKEN` is set, every supported request except `/health` must carry that bearer token, or the endpoint must answer 401. Unsupported methods are rejected with R002.1's 405 before authentication. Caller chain: the fan-manager console script (fan_manager/fan_manager.py:501) starts the node endpoint through start_from_env (fan_manager/node_api.py:138), which passes FAN_MANAGER_NODE_API_TOKEN to make_server; _Handler.do_GET (node_api.py:98) answers 401 when _authorized (node_api.py:92) fails, after answering /health. Shape: _authorized compares the Authorization header with hmac.compare_digest against the Bearer token held on the handler class; no token configured means open access. | `tests/test_fleet_endpoints.py::test_node_endpoint_requires_the_token` must pass. |
| `CONN-FAN-MANAGER-R003` | **Connector aggregation.** When `FAN_MANAGER_HOSTS` and `FAN_MANAGER_NODE_URL_TEMPLATE` are set, the connector must send each in-band read to every node endpoint and return the answers keyed by node name, from `fan_manager/fleet.py`. | `tests/test_fleet_endpoints.py` rows R003.1 to R003.5 pass. |
| `CONN-FAN-MANAGER-R003.1` | **Temperature by node.** `fan_manager_get_temp` must return one answer per node, keyed by the name each node reports. Caller chain: the fan-manager-mcp tool fan_manager_get_temp (action-routed in fan_manager/mcp/mcp_temperature.py:54) calls Api.get_temp (fan_manager/api_client.py:60), which calls fleet.read_all (fan_manager/fleet.py:71) when fleet.enabled (fleet.py:42). Shape: fleet.read_all fans out through ThreadPoolExecutor and _fetch (fleet.py:47) and keys results by the host field each node reports; reuses node_endpoints (fleet.py:26) for the target list. | `tests/test_fleet_endpoints.py::test_connector_aggregates_temperature_by_node` must pass. |
| `CONN-FAN-MANAGER-R003.2` | **In-band IPMI reads by node.** An IPMI read tool called without `host` must go to every node endpoint. A read with `host` stays out-of-band to that BMC. Caller chain: the fan_manager_ipmi_* tools registered through verbose_targets in fan_manager:connector (fan_manager/__init__.py:90) call IpmiApi methods such as power_status (fan_manager/ipmi_api.py:45) and sensors reads, which call fleet.read_all (fan_manager/fleet.py:71) when host is None and fleet.enabled. Shape: each IpmiApi read starts with the guard if host is None and fleet.enabled(): return fleet.read_all(<operation>); a read with host falls through to ipmi.<verb> with _target (ipmi_api.py:15). | `tests/test_fleet_endpoints.py::test_connector_routes_inband_ipmi_reads` must pass. |
| `CONN-FAN-MANAGER-R003.3` | **Writes stay guarded.** The connector must never send a write to a node endpoint. A write needs an explicit non-empty out-of-band `host`, `user`, and BMC `password`; missing any target field returns a typed 400 before the runner. Caller chain: IpmiApi write methods such as power_on (fan_manager/ipmi_api.py:55), reached through the fan_manager_ipmi_* tools of fan_manager:connector, call _write_guard (ipmi_api.py:21) before ipmi.power; no write path calls fleet.read_all. Shape: _write_guard returns a status 400 dict unless host, user and password are all non-empty, and writes always pass _target to ipmi.<verb>; fleet.py only defines GET reads via _fetch. | `tests/test_fleet_endpoints.py::test_connector_never_fans_out_writes` must pass. |
| `CONN-FAN-MANAGER-R003.4` | **Dead node is typed.** An unreachable node must appear as a 502 entry. The call must not raise. Caller chain: Api.get_temp (fan_manager/api_client.py:60) and the IpmiApi reads call fleet.read_all (fan_manager/fleet.py:71), which uses _fetch (fleet.py:47) per node. Shape: _fetch catches URLError, OSError and ValueError and returns a dict with status 502 and error node unreachable keyed by the base URL, so read_all never raises. | `tests/test_fleet_endpoints.py::test_unreachable_node_is_reported_not_raised` must pass. |
| `CONN-FAN-MANAGER-R003.5` | **Node names to endpoints.** Each `FAN_MANAGER_HOSTS` name must map to an endpoint through `FAN_MANAGER_NODE_URL_TEMPLATE`; a URL entry is used as is. Without the template, reads stay local, because `FAN_MANAGER_HOSTS` alone also names hosts for the derivation pass. Caller chain: fleet.enabled (fan_manager/fleet.py:42) is called by Api.get_temp (fan_manager/api_client.py:65) and IpmiApi reads, and calls node_endpoints (fleet.py:26) to turn FAN_MANAGER_HOSTS into URLs. Shape: node_endpoints formats each host into FAN_MANAGER_NODE_URL_TEMPLATE with str.format(host=...), keeps http(s) entries as is, strips trailing slashes and de-duplicates with dict.fromkeys; without a template only URL entries remain. | `tests/test_fleet_endpoints.py::test_hosts_map_through_the_url_template` must pass. |
| `CONN-FAN-MANAGER-R004` | **Engine identity.** The trend ingest at `fan_manager/fan_manager.py:75` must sign engine requests as `MEDULLA_PRINCIPAL` with audience `MEDULLA_AUDIENCE`, read by the shared SDK. The DaemonSet names `service:fan-manager` and `agent-services`. Shape: ingest_thermal_trend builds its engine client through _engine (fan_manager/kg_ingest.py:216) on scion_sdk.ingest KnowledgeIngest and SourceStream; the signer reads MEDULLA_PRINCIPAL and MEDULLA_AUDIENCE inside the SDK, so fan_manager sets neither itself. | `tests/test_engine_identity.py::test_trend_ingest_signs_as_the_configured_principal_and_audience` must pass. |
